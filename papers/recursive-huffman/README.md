# Recursive Huffman Compression

Paper: **Recursive Huffman Compression: An Experimental Systems Study**

## Research Question

What happens when Huffman compression is recursively applied to its own archive output, and when does an adaptive stopping rule prevent recursive layers from making an archive larger?

## Summary

This paper studies recursive Huffman compression as a systems experiment in the hz repository. It describes the Swift reference implementation, the versioned `.hz` archive format, adaptive and forced-depth recursive compression, recursive decompression, and benchmark tooling. The manuscript reports only measurements generated by the repository benchmark runner and verified by decompression.

## Status

Draft project manuscript. The repository does not provide evidence of peer review or external publication.

## Build

Build the paper and regenerate its committed table/figure fragments:

```sh
make -C papers/recursive-huffman
```

Clean LaTeX auxiliary files:

```sh
make -C papers/recursive-huffman clean
```

## Artifacts

Committed CSV snapshots live in `artifacts/data/`. They are benchmark outputs produced by `benchmarks/run.sh` and are used to generate:

- `tables/results-table.tex`
- `tables/passes-table.tex`
- `figures/trajectory.dat`
- `figures/trajectory-plot.tex`

After running a new recursive benchmark campaign, refresh the snapshots with:

```sh
cp benchmarks/results/csv/summary-adaptive-*.csv papers/recursive-huffman/artifacts/data/summary-adaptive.csv
cp benchmarks/results/csv/summary-baseline-*.csv papers/recursive-huffman/artifacts/data/summary-baseline.csv
cp benchmarks/results/csv/passes-adaptive-*.csv papers/recursive-huffman/artifacts/data/passes-adaptive.csv
make -C papers/recursive-huffman artifacts
```

## Relationship To hz

This paper documents the recursive/adaptive behavior implemented by `SwiftHuffmanEngine` and `RecursiveCompressionController`. It is about recursive compression behavior, not native backend performance. Implementation-level comparisons across Swift, Rust, and Rust streaming are tracked separately in `papers/implementation-benchmarks/`.
